# TASK: Deploy and Run Kandev on Replit

You are an expert DevOps + full-stack engineer.

Your job is to deploy the open-source project:

https://github.com/kdlbs/kandev

inside a Replit project so that the Kandev web UI is accessible through the Replit Preview/Webview.

## PRIMARY GOAL

Install and run Kandev successfully on Replit.

Expected result:

```text
Replit
  ↓
Kandev Server
  ↓
Web UI
  ↓
Replit Preview
```

The final application must be accessible through the Replit web preview URL.

Do NOT build a new Kanban application from scratch.

Use the official Kandev repository and preserve its existing UI and functionality.

---

# 1. PROJECT REQUIREMENTS

Repository:

https://github.com/kdlbs/kandev

Kandev is an AI Kanban & Development Environment.

Important capabilities that should remain available:

* Kanban / pipeline views
* task management
* agent orchestration
* multiple concurrent tasks
* git worktrees
* review workflow
* agent sessions
* terminal integration
* Claude Code
* Codex
* OpenCode
* other supported agents
* web UI
* API/backend

The goal is to get the official Kandev application running, not to replace its architecture.

---

# 2. FIRST STEP: INSPECT THE REPOSITORY

Before modifying anything:

1. Clone or use the Kandev repository.
2. Inspect:

   * README.md
   * Dockerfile
   * Dockerfile.universal
   * docker-entrypoint.sh
   * Makefile
   * mise.toml
   * package.json files
   * apps/backend
   * apps/web
   * apps/cli
3. Determine the simplest production-capable startup path for Replit.
4. Prefer the official release / npm distribution when possible.
5. Only build from source if necessary.

Important:

Do NOT blindly run development servers such as:

```bash
make dev
```

unless necessary.

The primary goal is to expose one stable HTTP service for Replit.

---

# 3. PREFERRED INSTALLATION STRATEGY

Try the official npm/npx distribution first.

Preferred option:

```bash
npx kandev@latest
```

If that works reliably on Replit, use it.

Alternative:

```bash
npm install -g kandev@latest
kandev
```

Do not install unnecessary development dependencies if the official binary/package already contains the web frontend and backend.

Kandev's web frontend is embedded into the application server, so the production runtime should ideally expose a single HTTP server.

---

# 4. REPLIT PORT REQUIREMENT

This is critical.

Replit needs the application to listen on the port configured by the environment.

Inspect:

```bash
echo $PORT
```

The Kandev process must listen on:

```text
0.0.0.0:$PORT
```

NOT:

```text
127.0.0.1
localhost
```

If Kandev exposes a host/port configuration, use it.

Example target:

```bash
kandev --host 0.0.0.0 --port $PORT
```

If the actual Kandev CLI uses different flags, inspect:

```bash
kandev --help
```

and use the correct official arguments.

Do not invent unsupported flags.

---

# 5. CREATE A REPLIT START COMMAND

Create or modify the Replit run configuration so the project can be started with one command.

Preferred pattern:

```bash
npm run start
```

or another simple command that launches Kandev.

For example, if appropriate:

```json
{
  "scripts": {
    "start": "kandev"
  }
}
```

But first verify how Kandev handles the port.

Do not overwrite Kandev's existing package configuration unnecessarily.

If Replit's configuration requires a separate startup script, create:

```text
scripts/start-replit.sh
```

with logic similar to:

```bash
#!/bin/bash

set -e

echo "Starting Kandev..."
echo "PORT=${PORT}"

exec kandev
```

Adapt this to the actual Kandev CLI behavior discovered during installation.

---

# 6. REPLIT WEBVIEW

The final service must be reachable from the Replit Preview tab.

Verify:

```bash
curl http://127.0.0.1:$PORT
```

If the application does not respond:

1. inspect the process logs
2. check the listening socket
3. verify the port
4. verify bind address
5. verify Kandev startup configuration

Use:

```bash
ss -ltnp
```

or:

```bash
netstat -ltnp
```

if available.

The final state should look similar to:

```text
0.0.0.0:<PORT>  LISTEN
```

---

# 7. DO NOT LOSE KANDEV DATA

Kandev uses local state such as:

* SQLite database
* task data
* configuration
* worktrees

Kandev normally stores its worktrees and SQLite database under:

```text
~/.kandev
```

On Replit, determine whether that directory persists across restarts.

If necessary, create a persistent workspace location and configure Kandev accordingly.

Do NOT store important data in an ephemeral temporary directory.

Before changing the storage path:

1. inspect the official Kandev configuration
2. identify supported environment variables/configuration
3. use official settings where possible
4. document the resulting storage location

---

# 8. GIT SUPPORT

Kandev relies heavily on Git worktrees.

Verify:

```bash
git --version
```

Then verify:

```bash
git worktree --help
```

The application must have permission to create Git worktrees.

Create a small test repository if needed:

```bash
mkdir -p /tmp/kandev-test
cd /tmp/kandev-test
git init
echo test > README.md
git add .
git commit -m "test"
git worktree add ../kandev-worktree-test -b test-agent
```

If the test succeeds, clean it up.

Do not leave test repositories in production.



The main Kandev process must remain attached to the Replit run command.
